## Scope and source

Since macOS 0.9.115 (`1046193b000e5412ad75151e53a3fa1d0b9ffae5`):

- **#462, Kick chat (plan 066).** After three failed attempts the Kick
  provider goes to `waiting` with a plain reason (relay down, Kick HTTP
  status, no network) shown inline in the Stream Manager status bar. The app
  subscribes to Kick subs/renewals, gifted subs, KICKs and bans as optional
  events and falls back to chat, status and follows if Kick refuses one. The
  Kick viewer count is unknown ("waiting") until Kick marks the channel live.
  The web half (videorc-web#47, migration runner and 0016) is already
  deployed.
- **#464,** a `recording-degraded` warning is dismissed when the session is
  no longer recording or streaming and is ignored for any other session;
  FFmpeg startup evidence and the original failure reason are kept on
  Windows startup rejection (plan 067; the Intel startup stall itself is not
  claimed fixed).
- #460 (Windows/Linux Alpha OAuth secrets), #461 (0.9.115 record), #463
  (resumable release controller, opt-in and not enabled) and #465 (bump).
